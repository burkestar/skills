Job Runner — Job API → running pods · flow is left → right

⓪ runner-agent self-registers its runner pool + queues with run-scheduler at startup. Users ① manage job definitions (container specs) and jobs through job-api (via the edge gateway). Each job runs as one or more runs: job-api ② schedules a run on run-scheduler (S2S), which ③ hands it to runner-agent, which ④ writes a Kubernetes CRD; ⑤ separate in-cluster operators reconcile it into pods. Status flows back via run-monitor, which ⑥ watches the job pods (k8s informer) and ⑦ POSTs status to job-api's callback; ⑧ clients invoke the running job through the gateway.
